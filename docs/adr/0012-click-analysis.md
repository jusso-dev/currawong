# ADR 0012: Click-time page analysis and domain age

Status: Accepted

## Context

Feed and block-list verdicts miss newly registered credential sites and links hidden inside other gateways' wrappers. BEC scoring also needs modest domain-age and thread evidence. All enrichment remains optional; ordinary offline operation needs no additional service.

## Decision

- `currawong-link` shares bundled-PSL registrable-domain handling, offline wrapper decoding, guarded HTTP and RDAP between classify and click analysis. Only existing workspace dependencies are used.
- `[rdap]` is off by default. An enabled client downloads the IANA DNS bootstrap, selects the longest label-wise suffix and an HTTPS base, preserves its path, and queries `domain/<registrable-domain>`. Only RFC 9083 `registration` events for the requested `ldhName` establish age. Missing dates, unsupported HTTPS services and errors mean unknown. No WHOIS fallback or third-party age API.
- SQLite persists bootstrap data (24-hour refresh), registration timestamps (seven days) and negative answers/errors (six hours). Refresh is lazy on demand. Requests use deadlines, a shared concurrency cap and bounded bodies; scan enrichment also has a whole-pass deadline and domain budget. From and Reply-To take precedence over links. Own registrable domains are skipped before any lookup. Bootstrap and domain lookup redirects are refused.
- This is an explicit domain-only residency exception: domain names, DNS queries and the bootstrap request can leave Australia. No sender local part, recipient, message, attachment or full message URL is sent to RDAP. URL-domain scan enrichment separately needs `rdap.scan_urls = true`. Unknown age never becomes zero days.
- Policy gets `domain.new_sender`, `domain.new_reply_to`, `domain.new_url` and optional count `domain.youngest_days`. Threshold defaults to 30 days. Default and government packs add informational headers for new domains; age alone never quarantines.
- New BEC reasons weigh 0.1 for new From, 0.1 for a different new/look-alike Reply-To, and 0.15 for a possible thread hijack. Existing Reply-To and look-alike evidence still contributes. First-time history uses actual envelope recipients, tenant-scoped authenticated delivery records. Existing history has no delivered Message-ID index, so thread detection deliberately uses the brief's fallback: Re:/Fwd:/FW:/AW:/WG:, first-time sender, no nonempty In-Reply-To. References cannot be verified; a forged In-Reply-To can evade this fallback. The default `bec >= 0.6` threshold stays unchanged.
- `[click]` locally unwraps recognised Google, Safe Links, Proofpoint v2/v3, Facebook, Bing and embedded-destination Mimecast links. Additional exact redirector hosts may expose `url` or `u`. Ambiguous parameters, invalid embedded targets, malformed Proofpoint v3 wrappers, loops and exhausted hop limits block. Opaque Mimecast `/s/` tokens stay wrapped. Every original, intermediate and final URL is checked against the existing intel/block-list chain, including when a page verdict is cached.
- `click.fetch.enabled = false` by default. Enabled fetches manually follow HTTP redirects and meta refresh with one shared hop/byte/deadline budget. Each request resolves once, checks **every** answer and pins the approved addresses. Environment proxies, automatic redirects, cookies, credentials and referrers are absent; User-Agent is fixed. Only HTTP(S) and configured ports (80/443 default) are permitted. Loopback, RFC 1918, link-local, CGNAT, multicast, metadata and reserved/special-use IPv4/IPv6 space are refused. IPv4-mapped IPv6, NAT64, Teredo and 6to4 cannot bypass the guard. Test-only exact socket allowlists do not exist in production builds.
- Fetches are another explicit recipient-designated destination exception. They disclose the requested URL (including any token), appliance IP and fixed User-Agent, and can activate one-time links. No email body or attachment is sent. Both HTTP and HTTPS are supported; the port allowlist restricts destination ports, not schemes.
- Landing-page analysis is static: password/login forms, cross-site/unsafe form actions (including base URLs), configured brand names outside legitimate domains, captcha gates, JS location indicators (never executed), meta refresh and the existing HTML-smuggling detector. Strong evidence blocks; supporting evidence and unavailable/incomplete page checks warn. Cached results have bounded TTL and cardinality. There is no screenshot model or browser execution inside the gateway.
- `click.analyser.url` enables an optional JSON POST hook. The endpoint is residency-checked at startup and for each request, resolves **only to loopback**, is pinned and cannot redirect. Neither residency overrides nor `mode = "off"` remove its loopback requirement. Its payload is `{url, final_url, html}`; `html` is null unless explicitly enabled and is capped by `max_excerpt_bytes`. Response is `{verdict, brand, score, reasons}`; verdict is `clean`, `warn`, `block` or `blocked`, score is finite 0..1. Invalid responses and unavailable optional services warn; required ones block the click. SMTP deferral does not apply to an HTTP click.
- Warn pages issue a separate-domain HMAC continuation bound to the delivered token and inspected final destination, expiring in five minutes. Unsigned `proceed=1` cannot bypass a warning, and a fresh block always wins. Continuations can be replayed within their short lifetime. Clean and accepted warnings redirect directly to the inspected destination. Click JSON/event exports retain verdict, reasons and final URL even after a user continues.

## Upstream formats checked

Checked on 24 October 2026:

- [IANA live DNS bootstrap](https://data.iana.org/rdap/dns.json), publication `2026-10-22T23:00:04Z`, and [RFC 9224 sections 3–4](https://www.rfc-editor.org/rfc/rfc9224.html): `services` contains `[suffixes[], bases[]]`, with label-wise longest match. [RFC 9083](https://www.rfc-editor.org/rfc/rfc9083.html) defines registration events.
- [Proofpoint URL Decoder API](https://help.proofpoint.com/Threat_Insight_Dashboard/API_Documentation/URL_Decoder_API) publishes v2 `u=https-3A__...` and v3 `/v3/__...__;character-map!…` examples. Tests include its published v3 `a*test`/`Kw` example and generated v2 escapes/run maps. No vendor API is called.
- [Microsoft Safe Links overview](https://learn.microsoft.com/en-us/defender-office-365/safe-links-about) documents the datacentre subdomain wrapper. Parsing accepts its embedded `url` destination only.
- [Meta link shim design](https://engineering.fb.com/2012/09/14/security/a-faster-better-link-shim/) describes the wrapper; [Mozilla Rally's upstream link-resolution source](https://mozilla-rally.github.io/web-science/jsdocs/linkResolution.js.html#line80) documents Facebook shim parsing. [SearXNG's maintained Google parser](https://docs.searxng.org/_modules/searx/engines/google.html) extracts `/url?q=`. These and Facebook `u` extraction are deliberately narrow compatibility formats, not vendor stability guarantees.
- [SearXNG's maintained Bing implementation](https://docs.searxng.org/_modules/searx/engines/bing.html) documents `/ck/a?u=a1<base64url>`. No public Bing vendor decoding contract was found.
- [Mimecast URL Protect documentation](https://mimecastsupport.zendesk.com/hc/en-us/articles/34000364685715-Targeted-Threat-Protection-URL-Protect-Overview) describes managed links; current `/s/` tokens require vendor resolution. The vendor decoder API page returned HTTP 403 here. Embedded `url`/`u` values are supported; opaque token decoding is not claimed.

## Running an external analyser

Run Phishpedia, PhishIntention or a headless browser in a separate isolated service, then expose a small wrapper on `127.0.0.1` only (for containers, publish its port to loopback). Configure `click.analyser.url = "http://127.0.0.1:8099/analyse"`. The wrapper accepts the JSON contract above and returns normalised evidence. Currawong does not implement or download these ML systems, their models or browser automation.

Default to URL-only payloads. Enable HTML excerpts only when needed. The wrapper must independently enforce public-address pinning and redirect/byte/time limits for **all** browser requests and subresources, restrict egress and avoid credentials/cookies. Currawong guards only its POST, not network traffic made by the analyser. A wrapper that blindly opens URLs would reintroduce SSRF. Check each external tool/model licence separately; none is vendored or linked here.

## Limits

No live RDAP registry, commercial wrapper decoder, ML model or headless browser was exercised. IANA/provider documentation was read; all tests use generated benign HTML, seeded caches or in-process fakes. Static checks cannot identify every brand logo, obfuscated JS, iframe, form association or credential workflow. Captcha and unsupported encodings warn. Fetch errors warn and can be overridden; operators requiring stricter decisions should use a required analyser. There is no active bootstrap timer: the first lookup after TTL refreshes it. See [validation](../VALIDATION.md).
