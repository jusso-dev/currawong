# ADR 0010: Local outbreak protection and retrospective detection

Status: Accepted

## Context

A delivered attachment or link may become known malicious after delivery. An MSP gateway can also recognise repeated content across tenants before any single tenant sees a large campaign. Initial clean AV results do not establish that a new file is safe.

## Decision

- `[outbreak]` is off by default. When enabled, `spool.dir/outbreak.sqlite3` stages bounded scan metadata and marks delivered copies from the scheduler Deliver path, S/MIME delivery and quarantine release. Delivery means hand-off to the local delivery queue, as with sender history; it does not assert a downstream SMTP acknowledgement. Portal-held originals are not marked delivered.
- Metadata includes original and delivered-copy ids, tenant, direction, sender, recipients, first observation and delivery times, part SHA-256/content types, normalised URLs and similarity digests. No body text or local part paths are stored. At most 64 parts, 64 URLs (input capped at 2048 bytes; normalisation may expand escaping), 256 recipients and one body digest per scan. At most 64 attachment digests are computed; decoded-byte work is capped at 32 MiB per message. `max_messages` bounds metadata records; the oldest observation is evicted at capacity, which can shorten retro coverage. Retry and split-copy ids share a campaign id.
- Default retention is 14 days. A background pass purges old metadata, first sightings, expired clean-cache entries and retained bytes, checkpoints WAL and incrementally vacuums free pages. SQLite may keep some reusable pages; deletion is not secure erasure. Pending/quarantined observations participate in campaigns, but only records marked delivered can produce retro detections.
- Inbound risky attachments defer with `outbreak hold` until a fixed deadline measured from their first global SHA-256 sighting. `min_tenants` counts distinct tenants within the hold window. All recipient tenants are registered before the decision, so recipient order cannot change it. Retries and restarts preserve first sighting; the scheduler shortens its normal retry delay to the hold deadline. Other verdict floors and the existing scan-deferral cap remain effective. Outbound content is not held.
- Categories: executables, macro Office files, archives in messages with risky extracted members, disk images, HTML and SVG attachments, and PDF active-content flags. The parser does not expose parent/member identity, so a risky member conservatively selects all archive attachments in that message. Explicit unnamed HTML attachment disposition is included; ordinary HTML message bodies are excluded. Static content policies remain in force after the delay ends.
- An administrator SHA-256 allow-list and explicit expiring known-clean cache bypass only the delay. They do not override malware or policy decisions. Absence of an initial AV match never populates the known-clean cache. The cache API is a local adapter seam; no administrator API is introduced here.
- `tlsh2` 1.1.0 provides TLSH with a distance threshold of 100, including length. It has no runtime dependencies and is Apache-2.0 OR BSD-3-Clause. Crates.io metadata checked 25 October 2026: release 12 October 2025; `tlsh-fixed` 0.2.0 is another permissive alternative, last updated 4 July 2026. Context7 had no matching Rust TLSH entry; API and dependency list checked against the published crate source. No C library or native TLSH executable is linked.
- Candidate lookup uses eight indexed MinHash bands, each containing two of sixteen minima over five-byte shingles; a candidate must then meet TLSH distance. For short/low-entropy inputs without TLSH, at least eight equal minima confirm similarity. Normalised body text is lower case with URLs, digits, long tracking tokens and whitespace runs removed. Similarity reads only the first 256 KiB of a part and the first 64 KiB of decoded message bodies. Body text is supplied by the parser worker, excluding subjects and attachments. Hashes, URLs and LSH buckets have time-indexed lookups; at most 4096 candidate rows are inspected per assessment. Capped counts are lower bounds, noted on the report. LSH is approximate and can miss similar content.
- Policy sees `campaign`, `outbreak.held`, `campaign.messages`, `campaign.tenants`, `campaign.senders` and `outbreak.first_seen_minutes`. Counts are distinct messages, tenants and envelope senders across the configured window, including the current message once. Default and government packs add `X-Currawong-Campaign` with size at the configured threshold. Only that header's exact `{campaign.messages}` value is substituted; arbitrary template expansion is not introduced. Campaign size alone does not quarantine. Commented examples combine campaign, first-time sender and spam evidence.
- A successful intel feed replacement changes a stable local revision. Once a minute, the daemon processes a 256-row delivered-indicator page against current local intelligence, including URL parent-domain candidates; failed syncs and 304 replies do not change the revision. Durable cursors track progress, and new revisions restart the pass. Work is eventual, not synchronous with feed download. No per-message feed lookup leaves the box.
- `retain_parts_hours = 0` disables byte retention. When opted in, verified extracted bytes are staged during scanning in SQLite, capped by `max_part_bytes`, `max_retained_bytes` and the per-message work budget. Parts of undelivered mail may temporarily occupy the quota, but are never retro-scanned. Retained bytes expire independently of metadata. Quota exhaustion skips retention and adds a report note, without treating content as clean.
- A changed YARA rules generation/fingerprint or clamd `VERSION` triggers retained-part rescanning, one part per engine per background pass. Engine cursors are independent, so an unavailable engine cannot block the other. YARA matching stays in the sandboxed parser worker; clamd remains a separate socket service. Fingerprints and cursors persist across restarts. Failed scans do not advance the cursor and are logged for retry. Retention expiry may end coverage before a large backlog finishes; operators must size the window and quota accordingly. No YARA or clamd configuration means no corresponding engine scan.
- Retro detections enter a durable outbox keyed by delivered message, tenant, source/rule and indicator. The `Remediation` trait accepts each detection; default implementation logs that no mailbox adapter is configured. Successful notifications emit existing `verdict_changed` events (`deliver` to `retro_detection`), with the source and indicator in `changed_by`. Failed remediation remains pending. The outbox suppresses routine duplicates; a crash between notification and acknowledgement can repeat one, so adapters must be idempotent.

## Consequences

No Graph, Gmail or EWS mailbox clawback is implemented (#41/#51). Events and log messages report detection, not mailbox deletion. The existing signed event webhook exporter can carry verdict-change events; there is no new content-sending HTTP client or residency exception. False-positive rates and recall are unmeasured on real mail. Global campaign counts intentionally expose aggregate MSP-wide activity to policy, never another tenant's addresses or content.

The 80 MB release image budget remains in force. TLSH adds one small dependency with no transitive crates; a release container was not built in this disk-constrained worktree. Tests use generated benign markers and local fakes only.
